# Struggles - What went wrong or was hard
The main struggle for me occured when I started working with a larger dataset. My original approach stored full sequences and codon lists from the training data, which ended up being very heavy on memory and slowed everything down more than I expected. While training the HMM model, my kernel would disconnect before completion on most runs and the few times it didn't it ran for over 30 minutes. After getting some feedback, I tried using a generator to improve overall efficiency, while that worked, I was able to make the code even more efficient when I realized I didn't need to store the sequences at all. Once I changed the code to count codons directly while reading the file, the runtime imporved and the program became much more efficient.

My main learning obstacle was extending the Viterbi algorithm to return top k paths. I understood the basic concept of Viterbi, but tracking the multiple paths took a lot of trial and error. I also found myself repeatedly getting confused with the data structures of the dynamic programming tables and the probabilities. Even though I understood them conceptually, I had to keep visualizing them to understand the how they translated into code.

If I were starting over, I would consider memory and runtime efficiency much earlier while designing the pipeline. I would also implement the top k version of Viterbi in the prototype stage. Doing these would have saved me a lot of debugging and refactoring later on. 


# Algorithmic Lessons
The HMM with Viterbi is a good fit for this project because it models sequences with hidden states, in this case "adapted" and "not adapted" codon usage across viral genes. Since it is trained on human codon sequences and then applied to the viral genes, it provides a reasonable way to estimate adaptation along a sequence.

However, while this model is useful, it is a simplified representation of how biology actually works. Reducing adaptation to two states makes the model efficient and interpretable but oversimplifies the biological system and cannot capture all factors affecting gene expression or protein function. A more complex model could improve biological realism, but would increase computational cost and make training and decoding much harder to implement. Even extending viterbi to return top k paths was significanlty challenging and increased implementation complexity. 

What surprised me was how I felt like the key challenges of the algorithm would be in the conceptual aspect when we were learning it in class, but while actually implementing it, I found the key challenges were more with managing data structures, probabilities and efficieny rather the algorithmic idea itself.
